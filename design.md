# Design System Inspired by Spectr

## 1. Visual Theme & Atmosphere

Spectr's design system radiates a premium, forward-thinking energy grounded in a deep dark palette punctuated by vibrant purple. The aesthetic is minimalist yet bold, favoring stark contrast—crisp white text and UI surfaces against near-black backgrounds—paired with generous whitespace and geometric precision. Sharp edges (no border radius) reinforce a tech-first, no-nonsense character, while the signature purple (`{colors.primary}` — `#894DEF`) acts as the energetic counterpoint, drawing attention to primary actions and moments of emphasis. Typography is authoritative and modern, with aggressive tracking on display sizes that commands presence. The overall mood is sophisticated and purposeful: a tool for serious builders who demand clarity and efficiency.

**Key Characteristics**
- Deep dark foundation (`{colors.canvas}` — `#0D0D0D`) creating visual weight and focus
- High contrast between text (`{colors.on-primary}` — `#FAFAFA`) and surfaces
- Electric purple (`{colors.primary}` — `#894DEF`) as the primary action and brand anchor
- Sharp geometry—zero border radius across all components
- Negative letter-spacing on display typography for visual compression and impact
- Minimal shadow depth; color blocking replaces layered elevation
- Responsive typography that scales boldly across breakpoints

### Principles

- **Aggressive tracking on display sizes:** Large headlines use strong negative letter-spacing (up to -11.52px) to compress letterforms and create visual punch; this is a defining trait of the brand voice.
- **Weight hierarchy:** Display and heading roles favor 700–900 weights for authority; body text sits at 500–600 for legibility and calm.
- **Line-height discipline:** Headings use tight line-height (1.0–1.2) for compact, commanding presence; body text opens to 1.5–1.6 for reading comfort.
- **Code is monospace and uppercase:** Technical tokens use JetBrains Mono with uppercase transforms and letter-spacing to mark them as distinct, machine-readable text.
- **Font weight does semantic work:** Bold weights signal emphasis; regular weights (500) are default; the system avoids 400 entirely.

- **Strategy:** Full-bleed sections with responsive inner content containers; no fixed column grid at mobile/tablet (content reflows). Desktop layouts employ CSS Grid with 5-column strategy for complex sections.
- **Section Patterns:** Full-width hero bands with centered content; card grids that collapse from 5→3→1 column(s) across breakpoints.

### Whitespace Philosophy

Whitespace is deliberate and generous. Sections are separated by substantial vertical rhythm (`{spacing.band}` = 48px and above) to create breathing room and visual hierarchy. Inline whitespace uses tighter units (`{spacing.md}` = 16px for paragraph gaps, `{spacing.sm}` = 12px for list items) to maintain reading flow. The design favors "space as signal"—gaps between elements direct attention and define logical groupings.

### Border Radius Scale

- **None** (`{rounded.none}` = 0px): All interactive and structural components (buttons, cards, inputs, navigation) use sharp corners. The system is uniformly rectilinear; there are no pill-shaped or rounded variants.

### Border Widths

- **Thin** (1px): Card borders, dividers, input borders (default state)
- **Medium** (2px): Primary button border, strong accent lines
- No thick (3px+) borders measured; the system favors minimal stroke weight.

## 6. Depth & Elevation

| Level | Treatment | Use |
|---|---|---|
| Flat | No shadow; color blocking (surface change) | Cards, panels, default containers |
| Elevated (sm) | `rgba(0, 0, 0, 0.1) 0px 10px 15px -3px, rgba(0, 0, 0, 0.1) 0px 4px 6px -4px` | Dropdowns, floating UI, modals |

**Shadow Philosophy:** Spectr relies primarily on **color blocking** (surface color shifts) rather than shadows to define depth. The single shadow tier (`sm`) is reserved for floating/modal components that need to visually lift above the page. The effect is subtle—two-layer shadow with 10% opacity—reinforcing the minimalist, contemporary aesthetic. Most UI depth comes from background color contrast: canvas (`#0D0D0D`) → surface (`#171717`) creates visual separation without blur.

### Opacity Levels

The system employs opacity for state indication and visual softening:

- **100%** (`1.0`): Default, full-strength text and elements
- **94%** (`0.94`): Near-full opacity; subtle disabled or overlay softening
- **90%** (`0.90`): Slightly dimmed text or secondary layers
- **70%** (`0.70`): Disabled buttons or inactive states
- **65%** (`0.65`): Muted foreground or tertiary text
- **36%** (`0.36`): Low-contrast backgrounds, overlay tints, placeholder text

### Z-index / Layering

- **Base / Flat:** `z-index: 1` (default, unlifted elements)
- **Dropdown:** `z-index: 10` or `z-index: 50` (floating menus, select dropdowns—two tiers suggest fallback behavior)
- **Modal / Fixed:** Inferred to be higher than 50 (not explicitly measured; see Known Gaps)

## 7. Do's and Don'ts

### Do

- **Use the primary purple** (`{colors.primary}` — `#894DEF`) for all primary CTAs, active states, and brand moments—it is the visual anchor.
- **Maintain sharp corners** (0px border-radius) on all components; the rectilinear geometry is a core identity trait.
- **Apply negative tracking on display sizes** (use the specified letter-spacing values); this compression is a defining brand voice element.
- **Rely on color blocking for depth:** stack surface colors (`canvas` → `surface`) rather than layering shadows.
- **Space sections generously** with `{spacing.band}` (48px) and above; whitespace is a design tool, not wasted space.
- **Use high contrast** between `{colors.on-primary}` (`#FAFAFA`) text and dark backgrounds for readability and impact.
- **Employ the Inter font family** for all body and heading text; it is refined, modern, and consistent with the brand.
- **Weight text deliberately:** use 600+ for headings, 500–600 for body, reserving heavier weights (700–900) for display.

### Don't

- **Avoid rounded corners** or pill-shaped buttons; the system is sharp and modern, not organic or playful.
- **Don't invent new colors** outside the measured palette; the dark neutrals and purple create the mood—stick to them.
- **Do not layer multiple shadows** for depth; use the single-tier shadow only for floating UI (dropdowns, modals), and prefer color blocking otherwise.
- **Avoid positive (rightward) letter-spacing** on display headlines; the brand voice uses compression (negative tracking).
- **Don't use the decorative accent palette** (`{colors.accent-1}` through `{colors.accent-7}`) for functional UI; these colors have no defined role and will dilute the visual system.
- **Never reduce line-height below 1.0** on body text; the measured hierarchy respects legibility—don't compress body copy.
- **Avoid thin font weights** (400 or below); the system uses 500 as its minimum, ensuring weight and clarity.

**Derivation Note:** Breakpoints were identified by measuring where layout values (content column width, grid columns, heading size) actually changed during resize. The nav link visibility remained at 46+ across all measured viewports; a menu toggle appears to be conditional (see Navigation Behavior, below) rather than a hard breakpoint.

### Touch Targets

- **Minimum Interactive Size:** 44px (height of secondary buttons and nav links), expanded to 56px for primary CTAs
- **Padding Inside Targets:** At least `{spacing.md}` (16px) of padding inside buttons to accommodate text and maintain comfortable tap/click zones
- **Spacing Between Targets:** At least `{spacing.xs}` (8px) between adjacent interactive elements to prevent accidental activation

### Collapsing Strategy

- **Mobile (375px):** Full-width content with single-column layouts; cards stack vertically. Horizontal section padding collapses to 0px (full bleed). Typography scales down (display headings reduce to ~40–50px from 70+px on desktop).
- **Tablet (768px):** Content column widens to 704px; 3-column grid layouts for card grids. Heading sizes increase slightly (41–55px); section padding remains generous.
- **Desktop (1024px+):** Content column continues to expand; 5-column grid for complex layouts. Display headings scale progressively (55→78px). Horizontal section padding reaches max (typically 32px per side or full container width at 1376px).
- **Navigation:** Remains visible across all breakpoints as a horizontal menu (46 nav items visible at 375px, same count at 1440px). No hamburger menu collapse point observed in extraction.

## 9. Agent Prompt Guide

### Quick Color Reference

- **Primary CTA / Brand Accent:** Primary (`#894DEF`)
- **Page Background / Canvas:** Canvas (`#0D0D0D`)
- **Card / Panel Surface:** Surface (`#171717`)
- **Heading / Primary Text:** On Primary (`#FAFAFA`)
- **Body Copy / Secondary Text:** Body (`#B8B8B8`)
- **Tertiary / Muted Text:** Neutral-1 (`#6B6B6B`)
- **Borders / Hairlines:** Hairline (`#2E2E2E`)
- **Decorative Palette:** Accents 1–7 (no functional role; avoid for UI)

### Iteration Guide

1. **Start with the dark base:** All surfaces begin with `{colors.canvas}` (`#0D0D0D`) or `{colors.surface}` (`#171717`); this is non-negotiable.
2. **Purple is the only accent:** Use `{colors.primary}` (`#894DEF`) for all primary actions, active states, and brand emphasis; no other accent color has a defined role.
3. **Keep corners sharp:** Set `border-radius: 0px` on all components—buttons, cards, inputs, images. The system has no rounded variants.
4. **Text color is almost always on-primary:** Use `{colors.on-primary}` (`#FAFAFA`) for headings and primary labels; use `{colors.body}` (`#B8B8B8`) for body text; use `{colors.neutral-1}` (`#6B6B6B`) for disabled/tertiary.
5. **Typography hierarchy drives visual structure:** Display sizes (44px–288px) use aggressive negative letter-spacing; headings (16px–30px) use 600–700 weight; body (14px–19px) stays at 500–600. Never deviate from the measured table.
6. **Padding is modular:** Use `{spacing.md}` (16px) as the default; scale up/down by the power of 2 (8px, 12px, 24px, 32px, 48px). Consistency through modularity.
7. **Depth comes from color, not shadow:** Use one shadow tier (`sm`) only for floating UI. Everything else relies on surface color contrast.
8. **Opacity for state:** Disabled elements use 0.5–0.7 opacity; overlays use 0.36–0.65 opacity. Full opacity (1.0) is default.
9. **Responsive grid scales: 1→3→5 columns** across mobile/tablet/desktop. Full-width sections remain full-width; inner grids collapse.
10. **Measure everything in the extracted tokens:** Never estimate a value. If a color, font size, spacing unit, or shadow is not in the token list, either omit it or record it under "Known Gaps."

## 10. Known Gaps

- **No semantic color ramp:** The site does not declare error, success, warning, or info states. Do not invent a status palette.
- **No gradients or decorative meshes:** The extraction found no CSS gradients, mesh backgrounds, or animated overlays. Color blocking is the only depth mechanism.
- **10 decorative accent colors without assigned role:** `{colors.accent-1}` through `{colors.accent-7}` have no measured functional use. They appear in the extracted palette but are not assigned to any UI component role. Avoid using them for standard UI.
- **Interaction states only partially extracted:** Hover and focus states are documented in the raw extraction data, but not all transitions are complete. Specific hover colors for secondary buttons, links, and form inputs were referenced generically (e.g., `hsl(var(--primary-hover))`) without concrete hex values. Implement based on the primary and surface colors; where exact state behavior is uncertain, fall back to the base colors listed here.
- **Modal and fixed-layer z-index not explicitly measured:** The extraction found `z-index: 10` and `z-index: 50` for dropdowns; modal/fixed layers are inferred to be higher but were not directly measured.
- **Breakpoint collapse point for navigation unclear:** The nav remains visible at 375px with 46+ links. No hamburger menu toggle was observed; the collapse strategy may be conditional (e.g., for very small screens or specific page contexts) and is not fully defined.
- **Dark mode behavior not measured:** No light theme or dark-mode toggle was observed or extracted. This document describes the single measured theme (dark).
- **Surfaces behind authentication not visited:** The extraction covered 6 pages of public site; logged-in dashboards or account settings may have additional component patterns or color roles not reflected here.
- **CSS custom properties (HSL variables) used but not fully resolved:** Interaction states in the raw data reference `hsl(var(--primary))`, `hsl(var(--ring))`, etc. The actual HSL values these map to are not provided; use the hex equivalents listed in this document.
- **Overflow / scrolling behavior not measured:** Sticky headers, scroll anchors, or lazy-load patterns were not extracted.
- **Animation / motion timing not provided:** The extraction did not capture CSS transitions, durations, or easing functions. No motion values are available for this system.
